# Wizard Verification Protocol — WVP Specification

## Category

Proof-of-Project-Reality

## Builder

nightfall-wizard

## Core Sentence

Wizard Verification Protocol turns project claims into verifiable reality.

## Adversarial Principle

No claim without proof. No proof without reproduction. No verification without adversarial testing.

## Purpose

WVP is an independent verification protocol for checking whether a crypto or open-source project is technically, organizationally and economically real.

## Non-Goals

- WVP is not hype analysis.
- WVP is not investment advice.
- WVP is not a custody service.
- WVP is not a token.
- WVP is not a security guarantee.
- WVP is not a formal audit unless a separate formal audit scope exists.

## Core Rule

WVP does not evaluate what a project claims. WVP evaluates what a project can prove.

## Minimum Verification Areas

1. Code Reality
2. Developer Competence
3. Build Reproducibility
4. Claim-vs-Code Consistency
5. Security Posture
6. Development Dynamics
7. Risk
8. Overall Reality Verdict

## WVP Reality Verdict

- verified
- partially_verified
- not_verified
- warning

## WVP Levels

- WVP-0: not verifiable
- WVP-1: existence evidenced
- WVP-2: code and activity evidenced
- WVP-3: build reproducibility passed
- WVP-4: major claims mostly evidenced
- WVP-5: technically strongly verified
- WVP-X: warning; severe contradiction or high risk
