
# WVP Evidence Refresh Cadence

WVP evidence should be refreshed when the upstream project or WVP itself materially changes.

## Refresh triggers

Refresh evidence when:

- upstream version changes
- security documentation changes
- release workflow changes
- consensus-relevant documentation changes
- WVP checker behavior changes
- public report format changes
- release-pack contents change
- reviewer feedback is accepted
- issue-quality gate changes
- governance process changes

## Recommended cadence

- after each WVP milestone
- before each review request
- before each release-pack publication
- after meaningful upstream changes
- after security-relevant feedback

## Boundary

Refreshing evidence improves currency. It does not prove Nightfall safety.
