# AUNEYA Minimal Fair-Genesis Launch Path v0.1

Status: protocol research
Scope: fair-genesis launch preparation
Value status: no token launch by this document

## Purpose

This document defines the minimal AUNEYA fair-genesis launch path.

The goal is to prepare a decentralized open-source protocol start where no AUNEYA or neya are sold, preminted, manually allocated, centrally distributed or promised before final legal mainnet genesis.

This document does not launch mainnet.

This document does not create AUNEYA.

This document does not create neya.

This document does not create a real reward.

This document does not create market value.

This document does not make anything transferable.

## Minimal launch path

The intended AUNEYA launch path is:

1. Finish the open-source protocol code.
2. Do not create coins before final legal mainnet genesis.
3. Do not sell coins.
4. Do not manually allocate coins.
5. Do not request personal data in exchange for coins.
6. Do not hold wallets, keys or coins for other users.
7. Do not operate an exchange, broker, custody service or advisory service.
8. Do not communicate an official price or listing promise.
9. Publish a Final Genesis Notice before any mainnet genesis.
10. Start with genesis supply 0.
11. After final genesis, every user can run the software independently.
12. Units may arise only automatically from valid post-genesis protocol work.

## Pre-genesis rule

Before final legal mainnet genesis:

- AUNEYA is not live.
- no AUNEYA exists.
- no real neya exists.
- no mainnet balance exists.
- no transferable unit exists.
- no official price exists.
- no listing is promised.
- no public token sale exists.
- no premine exists.
- no ICO exists.
- no claim to future coins exists.
- no simulated_neya converts into mainnet neya.
- no testnet unit converts into mainnet neya.

## Genesis rule

A final AUNEYA mainnet genesis, if it ever happens, must follow these rules:

- genesis supply: 0 AUNEYA
- premine: no
- ICO: no
- sale: no
- manual allocation: no
- official price: no
- listing promise: no
- investment claim: no
- return, profit or yield promise: no
- automatic conversion from simulation: no
- automatic conversion from testnet: no
- automatic conversion from contribution history: no
- legal review before genesis: required

## Post-genesis rule

After final legal mainnet genesis:

- users run their own software
- users control their own wallets
- users control their own keys
- users do not need an account with the maintainer
- units arise only by final protocol rules
- units arise only from valid post-genesis Witness or ledger work
- no maintainer custody is required
- no central issuer manually distributes units
- no sale by the maintainer is required

## Decentralized participation rule

AUNEYA participation must be self-directed.

A user should be able to:

- download or build the open-source software
- generate or control their own wallet
- run the protocol client
- perform valid Witness or ledger work
- receive protocol-created units according to final protocol rules

The maintainer must not require:

- payment for coins
- registration for coins
- personal data for coins
- custody by the maintainer
- private key sharing
- a broker account with the maintainer
- exchange use controlled by the maintainer

## Communication boundary

Allowed public wording before final legal mainnet genesis:

- AUNEYA is an open-source protocol.
- AUNEYA is under protocol research and development.
- AUNEYA has no live mainnet yet.
- AUNEYA has no token sale.
- AUNEYA has no premine.
- AUNEYA has no official price.
- AUNEYA has no listing promise.
- AUNEYA uses local non-value simulation and testnet units before final genesis.
- Real AUNEYA or neya may only exist after final legal mainnet genesis.
- After final genesis, units may only arise from valid post-genesis protocol work.

Prohibited public communication categories:

- purchase solicitation
- investment solicitation
- value-increase claims
- return claims
- yield claims
- exchange-access promises
- trading-venue promises
- official valuation targets
- guaranteed future allocation claims
- simulation-to-mainnet conversion claims
- testnet-to-mainnet conversion claims

## Service boundary

The maintainer must not provide:

- custody of third-party assets
- custody of private keys
- exchange services
- brokerage
- investment advice
- portfolio management
- market making
- listing coordination
- paid token allocation
- paid token sale
- guaranteed liquidity
- fiat on-ramp
- fiat off-ramp

## Legal gate

Final mainnet genesis is not allowed until the following gate is complete:

- final protocol rules are fixed before launch
- fair-genesis rule is published
- no-conversion rule is published
- no-sale rule is published
- no-premine rule is published
- no-ICO rule is published
- no-official-price rule is published
- no-listing-promise rule is published
- public wording is reviewed
- service boundary is reviewed
- custody boundary is reviewed
- data-protection boundary is reviewed
- tax/accounting review is completed
- crypto-financial regulatory review is completed
- written legal review is completed for the target jurisdiction

## One-sentence launch model

AUNEYA should be released as open-source protocol software with genesis supply 0, no sale, no premine, no ICO, no official price, no listing promise, no maintainer custody, and units arising only automatically from valid post-genesis protocol work.
