## Purpose

This document defines the AUNEYA feedback workflow for external reviewers.

The workflow converts external reviewer feedback into structured GitHub issues without implying launch, token value, transferability, mainnet activity or financial opportunity.

## Feedback workflow

1. Reviewer reads the external reviewer packet.
2. Reviewer selects a review category.
3. Reviewer opens an issue using the AUNEYA external review issue template.
4. Reviewer provides a summary and file reference.
5. Reviewer selects a risk level.
6. Reviewer proposes a documentation or protocol clarification.
7. Maintainer triages the issue.
8. Maintainer records whether the issue is accepted, deferred, rejected or needs legal review.
9. Any accepted change must preserve the non-value simulation boundary.

## Issue template

The issue template is:

    .github/ISSUE_TEMPLATE/auneya_external_review.yml

The issue template captures:

- review area
- summary
- evidence or file reference
- risk level
- suggested change
- boundary confirmation
- legal-review dependency

## Review categories

Review categories are:

- terminology clarity
- public-claim scope
- privacy boundary
- abuse resistance
- local simulation reproducibility
- documentation completeness
- non-value boundary
- legal-review dependency
- implementation gap
- reviewer question

## Triage states

Maintainer triage states are:

- accepted
- needs clarification
- needs legal review
- needs technical review
- deferred
- rejected
- duplicate
- out of scope

## Boundary

The feedback workflow is not a launch process.

It creates no token.
It creates no market value.
It creates no transferability.
It activates no mainnet.
It is not investment advice.
It is not legal advice.
It is not a custody, broker, exchange or financial service.

Legal review is required before any public token launch, listing, sale, transferability or market-value communication.
