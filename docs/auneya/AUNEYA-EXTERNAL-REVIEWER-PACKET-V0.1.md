## Review categories

Reviewers should classify feedback into one or more review categories:

- terminology clarity
- public-claim scope
- privacy boundary
- abuse resistance
- local simulation reproducibility
- documentation completeness
- non-value boundary
- legal-review dependency
- implementation gap
- reviewer question

## Review questions

Reviewers should answer these review questions:

- Is the AUNEYA purpose understandable without insider context?
- Is the public-claim scope clear?
- Are private, authenticated, hacked, paywalled, credentialed or surveillance claims excluded clearly?
- Is the phone witness model understandable?
- Are pulse, micro-proof, prooflet and event terms consistent?
- Is the local simulation reproducible from documented commands?
- Is the non-value boundary visible enough?
- Is there any language that could imply token value, market value or profit?
- Is there any language that could imply mainnet readiness?
- Is there any language that could imply legal approval?
- What should be clarified before any external legal review?
- What should be clarified before any production implementation?
